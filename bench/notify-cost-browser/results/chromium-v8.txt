Notes on the run
================

Captured via the chrome-devtools MCP at the URL above. Server was the
`npm run bench:notify-cost` static server on :5175. Page settings: schema
N=1000, capacity=16, 1000 batches × 1000 iters per batch, 100 warmup
batches. Identical knobs to the Node bench in bench/Bridge.bench.ts.

Comparison vs the Node V8 bench from 0.6.11 CHANGELOG:
  - Node:    pull 1.30 μs, noNotify 1.20 μs, delta ~100 ns
  - Browser: pull 1.96 μs, noNotify 1.92 μs, delta  40 ns

Two differences between the two harnesses:
  1. Browser pull is ~600 ns slower than Node pull at the same schema.
     This is the per-call overhead of the batched performance.now()
     timing strategy plus general browser-frame overhead, not a real
     pull-cost difference. The two paths differ only in the notify call
     either way, so the per-engine delta is what matters.
  2. The browser delta (40 ns) is even smaller than the Node delta
     (~100 ns). Both numbers sit at the noise floor of their respective
     timers. The qualitative answer is the same: V8's notify with zero
     waiters is essentially free, both in Node and in Chromium.
