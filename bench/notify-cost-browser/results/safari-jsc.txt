Notes on the run
================

Captured via ngrok HTTPS tunnel from a Windows 11 host serving the bench
on localhost:5175. The tunnel preserved the COOP / COEP / CORP headers
intact — the report shows `isolated : true`, confirming SAB and high-
resolution timer access were available on iOS Safari through the tunnel.
No code changes needed for the tunnel path; ngrok is a transparent
reverse proxy for these headers.

Two unexpected findings beyond the wait-flag conclusion:

  1. JSC is FASTER per pull than browser V8 on this fixture. 880 ns
     median on a phone vs 1.96 μs on a desktop Chromium 148. Likely
     reasons: Apple Silicon's ARM64 + JSC's native intrinsics for
     typed-array operations; the Chrome browser context carries more
     sandbox / security overhead than the Node V8 path (which was
     1.30 μs in 0.6.11's bench/Bridge.bench.ts).

  2. JSC's tail is tight. p99 is 180 ns above median, p999/max is
     420 ns above. Comparable to V8, much tighter than SpiderMonkey
     (which was 3-7 μs above median on the p99/p999). Lower GC noise
     in tight typed-array loops on iOS than on desktop Firefox/x86_64.

These observations are tangential to the wait-flag question but they
do matter for downstream audio-thread jitter discussions — iOS Safari
may turn out to be the BEST target for tight-loop audio code, not the
worst, contrary to common assumption.
