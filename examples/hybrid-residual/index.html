webgpu-audio-bridge — hybrid residual-on-carrier demo

Demonstrates BridgeBlockConsumer.processAdd() — the additive sibling of the audio-rate process() path. The AudioWorklet generates a cheap CPU sawtooth at the slider frequency (zero-latency control response), then folds the GPU-computed harmonic-partial residual on top.

What you're listening for. Move the freq slider — pitch follows instantly because the fundamental lives on the CPU. Press "Simulate GPU stall" — in Hybrid mode the upper harmonics fade out for ~250 ms while the fundamental keeps playing (audible thinning, no click). In Replace mode the same stall produces audible silence / click because the worklet has nothing to write.

What this is showing

The pure block-mode process() path is the obvious "GPU samples → AudioWorklet" pattern but it inherits the mapAsync latency floor (~85 ms at depth 4) and glitches audibly when the producer stalls. The hybrid pattern splits responsibilities: the fundamental stays on the CPU at zero latency, the spectral richness rides the GPU lane with bounded latency. The ear can't lock to upper-harmonic envelope phase, so the residual's lateness is inaudible under steady-state; the carrier's zero-latency response covers the pitch dimension that the ear does localize tightly.
