webgpu-audio-bridge — stereo hybrid residual-on-carrier demo

The stereo sibling of the examples/hybrid-residual/ demo. Demonstrates BridgeBlockConsumer.processAddStereo(L, R, gain) — one atomic op that mixes channel 0 → left and channel 1 → right from an interleaved GPU residual (one ring, one f32Array(2 × blockSize)), advancing the sample cursor once so L and R stay sample-locked. The AudioWorklet generates a cheap CPU sawtooth (zero-latency pitch) into both channels, then folds the GPU harmonic-partial residual on top.

What you're listening for. Move the freq slider — pitch follows instantly (fundamental on the CPU). Raise Stereo width — the upper-harmonic layer widens across L/R while the fundamental stays centered. Press "Simulate GPU stall" — in Hybrid mode the harmonics fade on BOTH channels for ~250 ms while the (centered) fundamental keeps playing; processAddStereo leaves L and R untouched on ring-empty, so the carrier survives per channel — no click.

What this is showing

Stereo is the first feature every hybrid-residual adopter hits in the first 30 seconds. The lowest-risk shape keeps the wire format unchanged: the lone f32Array carries interleaved L,R,L,R… samples, and the consumer de-interleaves on its side via channels: 2. The only genuinely new surface is the cursor-advance contract — processAddStereo reads both channels from one window and advances once, so it is not two processAddChannel calls (which would desync L from R). See README §"Stereo / multichannel".
